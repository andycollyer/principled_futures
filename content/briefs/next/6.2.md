# Secure development and procurement

**What it measures.** Whether there is a written security standard that every AI system must meet, both those the organisation builds and those it buys, and whether anyone checks that it is met.

**Why it matters.** Many organisations buy AI rather than build it. If the supplier's security is taken on trust, the people whose data passes through the system, and those its outputs affect, carry a risk nobody examined. They cannot inspect the supplier.

**The UK position.** The National Cyber Security Centre's 2023 guidelines cover secure design, development, deployment and operation. The government's January 2025 Code of Practice builds on them; ETSI carried its provisions into a specification (April 2025) and a European Standard, EN 304 223 V2.1.1 (December 2025). On buying, the Code says an organisation using an external provider "shall undertake a due diligence assessment and should ensure that the provider is adhering to this Code of Practice". The Code is voluntary. The binding rules cover personal data only: UK GDPR Article 32 requires security appropriate to the risk, regularly tested, and Article 28, closest to buying, allows only processors giving sufficient guarantees, under a contract permitting audits and inspections. A Cyber Security and Resilience Bill is before Parliament.

**What good looks like.** Security requirements written into development practice and contracts. Suppliers give evidence of testing, not assurances. Systems are tested before release and when the model changes; consequential ones independently.

**Reading the answer.** A supplier questionnaire nobody reads is the common weak answer. Ask what was last rejected, or changed, because of a security finding.

**A defensible figure.** In a 2024 government survey of 350 UK businesses using or planning to use AI, 47% of those using it had no cyber security practices specific to AI.
