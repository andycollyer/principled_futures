# Secure development and procurement

**What it measures.** Whether there is a written security standard that every AI system must meet, both those the organisation builds and those it buys, and whether anyone checks that it is met.

**Why it matters.** Many organisations buy their AI rather than build it. If the supplier's security is taken on trust, the people whose data passes through the system, and those its outputs affect, carry a risk nobody examined. They did not choose the supplier and cannot inspect it.

**The UK position.** The National Cyber Security Centre's 2023 guidelines cover secure design, development, deployment and operation. The government's Code of Practice of January 2025 builds on them, and an ETSI specification of April 2025 carries the same provisions. On buying, the Code says an organisation that works with an external provider "shall undertake a due diligence assessment and should ensure that the provider is adhering to this Code of Practice". The Code is voluntary. The binding rule is narrower: where personal data is processed, UK GDPR requires security appropriate to the risk, regularly tested. A Cyber Security and Resilience Bill is before Parliament and is not yet law.

**What good looks like.** Security requirements written into development practice and into contracts. Suppliers give evidence of testing, not assurances. Systems are tested before release and again when the model changes; consequential ones are tested independently.

**Reading the answer.** A supplier questionnaire that nobody reads is the common weak answer. Ask what was last rejected, or changed, because of a security finding.

**A defensible figure.** In a 2024 government survey of 350 UK businesses using or planning to use AI, 47% of those already using it had no cyber security practices specifically for AI.
